Gateway endpoints

Plain /api/v1 convenience routes, local customer APIs, and Zainpay proxies. Each endpoint includes a sample response.

Composite deep-dive: composite-endpoints.html. Inline checkout: inline-checkout.html.

Authentication

  • Most routes: X-Api-Key: $GATEWAY_API_KEY
  • Upstream Zainpay: server ZAINPAY_API_KEY (Bearer)
  • POST /webhooks/zainpay: HMAC Zainpay-Signature
  • GET /health is open

Sample request

curl -H "X-Api-Key: $GATEWAY_API_KEY" \
  "$HOST/api/v1/zainbox/charg_0atrmzL5qsMFKGYPrahj"

Metadata on mutations

Mutating Zainpay proxies accept custom metadata that is persisted locally and never forwarded upstream. Successful responses include data.metadata.

Sample body

{
  "zainpay": { "...": "official Zainpay fields" },
  "metadata": { "orderId": "ord_123" }
}

Credentials

PUT

Upsert credentials

/credentials

One test + one live pair per customer. Seed sets privateKey = zainbox codeName. Responses omit privateKey by default; pass ?revealPrivateKey=true to include it. A privateKeySet flag indicates a secret is stored.

Body

customerId, environment (test|live), publicKey, privateKey, metadata, status

Sample response

{
  "id": "2b018720-a714-4e9e-861f-488e7e795d9f",
  "customerId": 1,
  "environment": "live",
  "publicKey": "eyJ0eXAiOiJKV1QiLCJhbGciOi\u2026",
  "privateKeySet": true,
  "status": "active"
}
