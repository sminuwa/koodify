Composite endpoints

Stable Koodify /api/v1/… paths that each call two Zainpay upstream endpoints and return one envelope. If Zainpay renames an upstream URL, only the mapping changes — your integration path stays the same. Nested fields keep the original Zainpay ApiResponse so you can still read each upstream code.

Full gateway catalogue: docs/api.html. Inline checkout: docs/inline-checkout.html. Principle: FEATURES.md · Stable Koodify API surface.

Auth & response shape

  • Gateway auth: X-Api-Key (same as other koodify routes).
  • Upstream auth: merchant ZAINPAY_API_KEY on the server.
  • Outer envelope uses code: "00" when both HTTP calls succeed.
  • SDK: client.composite().…().
{
  "code": "00",
  "status": "200 OK",
  "description": "composite: …",
  "data": {
    "firstPart": { "code": "00", "status": "…", "description": "…", "data": { } },
    "secondPart": { "code": "00", "status": "…", "description": "…", "data": { } }
  }
}

GET

Zainbox snapshot

/api/v1/zainbox/{zainboxCode}

Dashboard header for one zainbox: profile plus account balances.

Combines

  • GET /zainbox/profile/{zainboxCode}
  • GET /zainbox/accounts/balance/{zainboxCode}

data fields

profile, balances

SDK

client.composite().zainbox_snapshot(code).await?

Example

curl -H "X-Api-Key: $GATEWAY_API_KEY" \
  "$HOST/api/v1/zainbox/charg_0atrmzL5qsMFKGYPrahj"
